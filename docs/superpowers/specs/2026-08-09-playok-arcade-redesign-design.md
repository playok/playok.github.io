# PLAYOK ARCADE — 프로필 & 홈페이지 리디자인 설계

작성일: 2026-08-09

## 1. 배경

`github.com/playok`는 프로필 README가 없어 저장소 목록만 노출된다. bio도 비어 있다.
`playok.github.io`는 2020년 8월 이후 방치되어 있고, `index.html`은 PIXI 샘플 링크 두 줄뿐이며 `css/main.css`는 빈 파일이다.

공개 저장소 14개는 Go·Rust·C 기반 시스템/인프라 유틸리티가 중심이지만, 방문자에게 그 정체성이 전혀 드러나지 않는다.

기여 활동은 그 자체로 강한 근거다. 총 4,878건이며, 2022년부터 연 500건대를 유지하다 2026년에 5배로 뛰었다. 비공개 저장소 기여가 프로필에 포함되도록 이미 설정되어 있어, 로그인하지 않은 방문자에게도 같은 수치가 보인다.

## 2. 목표

1. 방문자가 3초 안에 "저수준 시스템 도구를 꾸준히 만드는 개발자"임을 인지한다.
2. 기여량과 그 증가 추세를 한눈에 보이게 만든다.
3. 프로필과 홈페이지가 하나의 비주얼 아이덴티티를 공유한다.
4. 외부 서비스 의존 없이 저장소 안에서 완결된다.

**비목표**: 블로그 기능, CMS, 빌드 파이프라인 도입.

## 3. 컨셉

**`PLAYOK ARCADE`** — 닉네임 `playok`이 "Play OK"로 읽히는 점을 축으로 삼는다.
개발자는 플레이어 캐릭터, 저장소는 클리어한 스테이지, 기술 스택은 스탯, 기여 기록은 하이스코어다.
16비트 아케이드 캐비닛의 CRT 화면을 시각적 은유로 사용한다.

### 3.1 디자인 토큰

두 산출물이 동일한 값을 쓴다. 홈페이지는 CSS 커스텀 프로퍼티로, SVG는 하드코딩한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#0d0221` | 화면 바탕 (딥 퍼플) |
| `--bg-panel` | `#190b3d` | 카드·패널 바탕 |
| `--cyan` | `#00f0ff` | 주 액센트, 제목, 링크 |
| `--magenta` | `#ff2e88` | 보조 액센트, 강조 |
| `--yellow` | `#ffd700` | 스탯 게이지, 별, 하이스코어 |
| `--green` | `#39ff14` | 상태 표시(ACTIVE), 성공 |
| `--text` | `#e8e6f0` | 본문 |
| `--text-dim` | `#8b86a8` | 부가 정보 |

- **폰트**: `"Press Start 2P"`(Google Fonts) → `ui-monospace, "SF Mono", Consolas, monospace` 폴백. 픽셀 폰트는 제목·라벨 등 짧은 문구에만 쓰고, 본문은 가독성을 위해 모노스페이스를 쓴다.
- **질감**: 2px 간격 CRT 스캔라인 오버레이, 사각 픽셀 보더(둥근 모서리 없음), 별 배경.
- **모션**: 깜빡임(`PRESS START`), 타이핑, 카드 호버 시 상승. 전부 `prefers-reduced-motion: reduce`에서 정지.

### 3.2 스테이지 분류

13개 저장소(`playok.github.io` 자신은 제외)를 4개 월드로 묶는다. 프로필과 홈페이지가 같은 분류를 쓴다.

| 월드 | 저장소 |
|---|---|
| **WORLD 1 — SERVER OPS** | `jvm-oom-guardian`, `TomcatKit`, `only1mon`, `pg19-simd-check` |
| **WORLD 2 — DESKTOP TOOLS** | `devup`, `DevHome_Relocator`, `synergy-hangul-fix` |
| **WORLD 3 — WEB & DATA** | `gitNotepad`, `ParquetDuckQuery`, `packetDup`, `kr-supercharger-timeline` |
| **WORLD 4 — AI & SIGNAL** | `mcp-glm-go`, `audio-modem` |

`audio-modem`은 GitHub 설명이 비어 있다. 저장소 코드를 읽고 한 줄 설명을 작성해 넣는다.

### 3.3 언어 정책

게임 UI 라벨(`HP`, `EXP`, `STAGE`, `HIGH SCORE`, `PRESS START`, `WORLD 1`)은 영어로 고정한다. 프로젝트 설명과 소개 문구는 한국어로 쓴다. 영문 설명만 있는 저장소는 한국어로 옮긴다.

## 4. 기여 통계 — 수집과 갱신

프로필과 홈페이지가 공유하는 핵심 데이터다. 수집 방식을 먼저 정의한다.

### 4.1 지표

2026-08-09 기준 확인값이며, 이후 자동 갱신된다.

| 지표 | 표기 | 현재값 |
|---|---|---|
| 총 기여 (2010~) | `HIGH SCORE` | 4,878 |
| 올해 기여 | `2026 SCORE` | 2,583 |
| 최장 연속 기여일 | `MAX COMBO` | 19 |
| 현재 연속 기여일 | `NOW` | 14 |
| 하루 최다 기여 | `BEST DAY` | 68 |
| 올해 활동일 비율 | 게이지 | 171 / 221일 |
| 연도별 기여 | 막대 그래프 | 2015~2026 |

연도별 값(2015: 19, 2016: 14, 2017: 269, 2018~2020: 각 2, 2021: 37, 2022: 548, 2023: 500, 2024: 523, 2025: 378, 2026: 2,583)은 막대 그래프로 그린다. **2026년이 직전 최고치의 4.7배라는 사실이 가장 강한 근거이므로, 올해 막대는 다른 색(마젠타)으로 칠하고 `NEW RECORD` 배지를 붙인다.**

### 4.2 수집 방법

`https://github.com/users/playok/contributions?from=YYYY-01-01&to=YYYY-12-31`을 연도별로 요청해 파싱한다. 인증이 필요 없고, 비공개 저장소 기여까지 포함된 값이 나온다.

응답 HTML의 각 날짜 칸은 `data-date="YYYY-MM-DD"` 속성을 가지며, 실제 기여 수는 대응하는 툴팁 요소의 `N contributions on …` 텍스트에 담긴다. 이 둘을 이어 일별 값을 만들고, 합계·연속일·최댓값을 계산한다.

검증: 2022년을 이 방식으로 합산한 값(548)이 GraphQL API 값과 일치함을 확인했다.

### 4.3 자동 갱신

GitHub Actions가 매일 1회(UTC 21:00 = KST 06:00) 실행되어 수치를 다시 수집하고, 결과물을 커밋한다. 수동 실행(`workflow_dispatch`)도 가능하게 한다.

- 기본 `GITHUB_TOKEN`만 사용한다. 별도 PAT이나 Secret 등록이 필요 없다.
- 두 저장소가 각각 자기 워크플로를 가진다. 한 저장소의 Actions가 다른 저장소에 푸시하려면 PAT이 필요해지므로 그렇게 하지 않는다.
- 수치에 변화가 없으면 커밋하지 않는다.
- 수집이나 파싱에 실패하면 워크플로를 실패로 끝내고 **기존 파일을 건드리지 않는다.** GitHub이 페이지 구조를 바꿔 갱신이 멈추더라도 마지막으로 성공한 화면이 그대로 남는다.

## 5. 산출물 A — 프로필 README

### 5.1 저장소

`playok/playok`을 새로 만든다(public). GitHub이 이 저장소의 `README.md`를 프로필 상단에 렌더한다.

```
playok/
  README.md
  assets/
    title.svg          # ① 타이틀 화면 배너
    stats.svg          # ② 플레이어 스탯 카드
    score.svg          # ③ 하이스코어 보드 (자동 갱신 대상)
  scripts/
    build_score.py     # 기여 수집 → score.svg 생성
  .github/workflows/
    update-score.yml   # 매일 실행
```

### 5.2 구성

| 블록 | 형식 | 내용 |
|---|---|---|
| ① TITLE SCREEN | `assets/title.svg` (900×280) | 픽셀 로고 `PLAYOK`, 별 배경, 스캔라인, `▶ PRESS START` 1.2초 주기 깜빡임(SMIL `<animate>`) |
| ② PLAYER STATS | `assets/stats.svg` (900×320) | `CLASS: Systems Engineer` / `GUILD: PentaSystem inc.` / `LOC: Seoul, KR` / `SINCE: 2010` + 언어별 EXP 게이지 |
| ③ HIGH SCORE | `assets/score.svg` (900×360) | 4.1의 지표 전체. 총점, 콤보, 연도별 막대 그래프, `NEW RECORD` 배지 |
| ④ INVENTORY | 마크다운 | 월드별 소제목 + 저장소 표(이름·설명·언어). 각 이름은 저장소 링크 |
| ⑤ CURRENT QUEST | 마크다운 목록 | 진행 중인 관심사 3~4줄 |
| ⑥ CONTACT | 마크다운 | sarangsai.com, GitHub 프로필 |

`stats.svg`의 EXP 게이지는 공개 저장소의 주 언어 개수를 기준으로 채운다: Go 4, Rust 3, HTML 3, JavaScript 3, C 1. 이 값은 자주 바뀌지 않으므로 자동 갱신 대상이 아니다.

### 5.3 테마 대응

SVG가 자체 배경(`#0d0221`)을 칠하므로 GitHub 라이트/다크 테마 양쪽에서 동일하게 보인다. 별도 `<picture>` 분기는 두지 않는다.

README의 마크다운 본문에는 색을 지정하지 않는다. GitHub이 테마에 맞춰 렌더하도록 맡겨, 라이트 모드에서 글자가 사라지는 사고를 원천 차단한다.

### 5.4 제약

GitHub README는 CSS와 JS를 제거한다. 따라서:
- 그래픽은 전부 SVG 파일을 `![](assets/….svg)`로 임베드한다.
- SVG 애니메이션은 SMIL(`<animate>`, `<animateTransform>`)로만 작성한다. SVG 내부 `<style>`의 CSS 애니메이션은 렌더러에 따라 무시될 수 있어 쓰지 않는다.
- 레이아웃은 마크다운 표와 이미지 정렬로만 구성한다.
- GitHub은 이미지를 프록시로 캐시한다. 갱신된 `score.svg`가 즉시 반영되지 않을 수 있으나, 캐시는 수 분 내 만료된다.

## 6. 산출물 B — playok.github.io

### 6.1 파일 구조

```
playok.github.io/
  index.html              # 단일 페이지
  css/main.css            # 현재 빈 파일 → 전면 작성
  js/main.js              # 신규
  assets/
    stats.json            # 기여 수치 (자동 갱신 대상)
  scripts/
    build_stats.py        # 기여 수집 → stats.json 생성
  .github/workflows/
    update-stats.yml      # 매일 실행
  pixi/                   # 기존 유지 (수정하지 않음)
  README.md               # 기존 유지
```

빌드 도구·프레임워크·외부 JS 라이브러리를 쓰지 않는다. GitHub Pages가 정적 파일을 그대로 서빙한다.

### 6.2 섹션

| 순서 | 섹션 | 내용 |
|---|---|---|
| 1 | **TITLE** | 전체 화면 높이. 픽셀 로고, 타이핑 효과로 출력되는 한 줄 소개, 아래로 스크롤 유도 `▼` |
| 2 | **HIGH SCORE** | 4.1의 지표. 숫자는 화면에 들어올 때 0부터 카운트업하고, 연도별 막대는 차례로 차오른다 |
| 3 | **SELECT STAGE** | 3.2의 월드별 그룹. 저장소마다 카드 하나(이름·설명·언어 배지·GitHub 링크). 반응형 그리드 |
| 4 | **DEMO** | 기존 PIXI 샘플 3개 링크. 캐비닛 화면 프레임 안에 배치 |
| 5 | **PLAYER** | 소개, 소속, 위치, 연락처(sarangsai.com, GitHub) |

전역 오버레이로 CRT 스캔라인과 비네트를 얹는다(`pointer-events: none`).

### 6.3 데이터

- **기여 수치**: `assets/stats.json`을 같은 오리진에서 `fetch`한다. HTML에 마지막 확인값을 직접 적어두고, fetch가 성공하면 그 값으로 교체한다. **JS가 실패하거나 꺼져 있어도 숫자가 보인다.**
- **저장소 목록**: `js/main.js`의 배열 상수로 둔다. GitHub API를 호출하지 않는다 — 비인증 API는 시간당 60회로 제한되고, 방문자가 빈 화면을 보게 될 위험이 실익보다 크다. 저장소가 늘면 배열에 한 줄 추가한다.

### 6.4 반응형

- 브레이크포인트: 640px(모바일 1열), 960px(태블릿 2열), 그 이상 3열.
- 픽셀 폰트는 `clamp()`로 크기를 조절한다.
- 가로 스크롤이 발생하지 않아야 한다.

### 6.5 접근성

- 색 대비: 본문 텍스트는 배경 대비 4.5:1 이상을 만족한다. 네온색은 큰 제목과 장식에만 쓴다.
- `prefers-reduced-motion: reduce`에서 스캔라인 흐름·타이핑·깜빡임·카운트업·호버 이동을 모두 끈다. 카운트업이 꺼지면 최종 수치를 즉시 표시한다.
- 모든 링크는 키보드 포커스 링을 가진다.
- 장식용 SVG는 `aria-hidden="true"`, 의미 있는 이미지는 `alt`를 지정한다.
- 하이스코어 막대 그래프는 수치를 텍스트로도 제공해 스크린 리더가 읽을 수 있게 한다.

## 7. 검증

1. 수집 스크립트: 2022년 합계가 548, 2025년이 378로 나오는지 확인한다.
2. 홈페이지: 로컬 정적 서버로 띄운 뒤 Playwright로 데스크톱(1440px)·모바일(390px) 스크린샷을 찍어 확인한다.
3. `prefers-reduced-motion` 에뮬레이션 상태에서 애니메이션이 멈추고 수치가 즉시 보이는지 확인한다.
4. `stats.json` 요청을 차단한 상태에서도 숫자가 표시되는지 확인한다.
5. 프로필 README: `playok/playok`에 푸시한 뒤 `github.com/playok`을 라이트/다크 테마 양쪽에서 확인한다.
6. 두 워크플로를 수동 실행해 성공하는지, 변경이 없을 때 커밋하지 않는지 확인한다.
7. 콘솔 에러가 없어야 한다.

## 8. 작업 순서

1. 기여 수집 스크립트를 만들고 검증한다(7-1). 두 산출물이 이 데이터에 의존하므로 먼저 확정한다.
2. 디자인 토큰과 픽셀 로고 SVG를 확정한다(두 산출물의 공통 자산).
3. 홈페이지를 구현하고 스크린샷으로 검수받는다.
4. 확정된 톤 그대로 프로필 README용 SVG 3종과 README를 작성한다.
5. 두 저장소의 워크플로를 추가한다.
6. `playok/playok` 저장소를 생성해 푸시한다.
7. `playok.github.io`를 푸시한다.

푸시는 각 단계에서 사용자 확인을 받은 뒤 실행한다.
